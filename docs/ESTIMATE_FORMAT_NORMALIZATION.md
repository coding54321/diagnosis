# 견적서 양식 정규화 가이드

다양한 견적서 양식을 우리 앱의 표준 데이터 구조로 변환하는 방법을 정리한 문서입니다.

---

## 1. 표준 데이터 구조

우리 앱에서 사용하는 견적서 데이터 구조:

```typescript
{
  shopName: string;        // 정비소명
  date: string;            // 의뢰일자 (YYYY-MM-DD)
  registrationNumber?: string; // 차량번호
  items: Array<{
    name: string;          // 정비 항목명
    partCost: number;      // 부품비
    laborCost: number;     // 공임비/기술료
    totalCost: number;     // 소계 (부품비 + 공임비)
    category: string;      // 카테고리 (엔진, 제동, 변속기, 전기, 냉각, 배기, 기타)
  }>;
  totalAmount: number;     // 총 금액
  vatIncluded: boolean;    // 부가세 포함 여부
  vatAmount?: number;      // 부가세 금액
}
```

## 2. 실제 견적서 양식 예시

### 2.1 표준 양식 (무상수리/유상수리 구분)

**예시: 블루멤버스/현대 정비소 견적서**

```
자동차 점검·정비명세서 (고객용)

[차량 정보]
- 차량번호: 12가3456
- 차종: 쏘나타YF
- 주행거리: 51,946 km
- 의뢰일자: 2025-01-11

[정비소 정보]
- 업체명: 석촌현대자동차서비스 최영현

[정비 내역]

<무상수리>
- 소요부품: 저마찰 엔진오일 (수량: 1, 금액: 0)
- 작업내용: 엔진 오일 교환 (기술료: 0)

<유상수리>
- 소요부품: 필터-에어 클리너 (수량: 1, 단가: 7,500, 금액: 7,500)

[금액 합계]
```

## 3. 다양한 양식 변형 처리

### 3.1 부품과 작업이 분리된 경우

**문제:** 견적서에서 부품명과 작업명이 별도 행으로 표시됨

**예시:**
```
NO 1: 소요부품 - 필터-에어 클리너 (7,500원)
NO 1: 작업내용 - 에어 클리너 필터 (22,000원)
```

**처리 방법:**
1. 이름이 유사한 부품/작업 쌍을 찾기
2. 하나의 항목으로 합치기: `name="에어 클리너 필터 교체"`, `partCost=7500`, `laborCost=22000`

**코드:** `normalizeOCRItems()` 함수에서 자동 처리

---

### 3.2 무상수리 항목 처리

**문제:** 무상수리 항목은 금액이 0이지만 항목으로 포함해야 함

**처리 방법:**
- `partCost: 0`, `laborCost: 0`, `totalCost: 0`으로 저장
- 항목명은 유지 (예: "엔진 오일 교환")

---

### 3.3 부품비/공임비가 합쳐진 경우

**문제:** 일부 견적서는 부품비와 공임비를 구분하지 않고 "소계"만 표시

**예시:**
```
브레이크 패드 교체: 160,000원 (부품비+공임비 합계)
```

**처리 방법:**
- `partCost: 0`, `laborCost: 0`, `totalCost: 160000`으로 저장
- 또는 AI가 추론 가능하면 분리 (예: 항목명에서 "부품" 키워드가 있으면 partCost로 분류)

---

### 3.4 항목명만 있고 금액이 없는 경우

**문제:** 일부 견적서는 항목명만 나열하고 금액은 총액만 표시

**처리 방법:**
- `partCost: 0`, `laborCost: 0`, `totalCost: 0`으로 저장
- Review 화면에서 사용자가 수동으로 입력하도록 유도
- `status: 'PARTIAL'`로 표시

---

### 3.5 카테고리 자동 분류

**규칙:**
- **엔진**: 오일, 필터, 에어클리너, 엔진 관련
- **제동**: 브레이크, 패드, 디스크, 제동 관련
- **변속기**: 미션, 클러치, 변속기 관련
- **전기**: 배터리, 라이트, 전구, 전기 관련
- **냉각**: 라디에이터, 워터펌프, 냉각 관련
- **배기**: 머플러, 촉매, 배기 관련
- **기타**: 위에 해당하지 않는 경우

**코드:** `inferCategory()` 함수에서 항목명 기반 자동 분류

## 4. OpenAI Vision API 프롬프트 개선

### 4.1 프롬프트에 포함된 지침

1. **다양한 양식 인식**
   - 무상수리/유상수리 구분 양식
   - 부품/작업 분리 표
   - 통합 리스트 양식

2. **부품+작업 합치기**
   - 이름이 유사한 부품/작업 쌍을 하나의 항목으로 합치기
   - 예: "필터-에어 클리너" + "에어 클리너 필터" → "에어 클리너 필터 교체"

3. **누락 값 처리**
   - 부품비 없으면 `partCost: 0`
   - 공임비 없으면 `laborCost: 0`
   - 소계 없으면 `partCost + laborCost`로 계산

4. **카테고리 추론**
   - 항목명에서 키워드 기반 자동 분류

## 5. 테스트 케이스

### 케이스 1: 표준 양식 (무상/유상 구분)
- ✅ 부품과 작업 분리 인식
- ✅ 무상수리 항목 포함 (금액 0)
- ✅ 유상수리 항목 정확히 추출

### 케이스 2: 통합 리스트 양식
- ✅ 모든 항목이 하나의 리스트로 표시
- ✅ 부품비/공임비가 함께 표시된 경우 분리

### 케이스 3: 부분 정보만 있는 경우
- ✅ 항목명만 있고 금액 없는 경우 처리
- ✅ 총액만 있고 항목별 상세 없는 경우 처리

---

## 6. 구현 위치

- **OCR 함수:** `lib/openai/vision.ts`
  - `analyzeEstimateImage()`: OpenAI API 호출 및 기본 파싱
  - `normalizeOCRItems()`: 다양한 양식을 표준 구조로 정규화
  - `inferCategory()`: 항목명에서 카테고리 추론

- **데이터 흐름:**
  1. 촬영/앨범 → 이미지 업로드
  2. `analyzeEstimateImage()` 호출
  3. `normalizeOCRItems()`로 정규화
  4. Review 화면에 표시
  5. 사용자 수정 가능
  6. 검증하기 → DB 저장

---

이 가이드를 따라 다양한 견적서 양식을 일관된 데이터 구조로 변환할 수 있습니다.
