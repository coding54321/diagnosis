# 차량 등록번호·소유주 인증 관련 로직 정리

견적서 확인 페이지(`app/(main)/verify/review/page.tsx`)에 추가된 **차량번호 + 소유주 확인** 플로우와 관련 코드를 정리한 문서입니다.

---

## 1. 타입·상태 정의

### 1.1 차량 확인 단계 (`VehicleVerificationStep`)

```ts
type VehicleVerificationStep = 'input' | 'checking' | 'owner' | 'confirming' | 'confirmed';
```

| 단계 | 의미 |
|------|------|
| `input` | 차량등록번호 입력 대기 |
| `checking` | 차량 정보 조회 중 (`fetchVehicleByRegistrationNumber` 호출 중) |
| `owner` | 조회 성공 후 **소유주 이름** 입력 대기 |
| `confirming` | (코드 상 정의만 있고, 현재 플로우에서 설정되는 곳 없음 — `owner`와 동일 블록에서 사용) |
| `confirmed` | 소유주 확인 완료 → **검증하기** 버튼 활성화됨 |

### 1.2 관련 state (review 페이지)

| State | 타입 | 용도 |
|-------|------|------|
| `vehicleStep` | `VehicleVerificationStep` | 위 단계값. 기본 `'input'` |
| `ownerName` | `string` | 사용자가 입력한 **소유주명** (차량등록증 기재명) |
| `vehicleCheckError` | `string \| null` | 차량 조회/소유주 확인 시 표시할 에러 메시지 |
| `vehicleNumber` | `string` | 차량등록번호 (표시·조회용) |
| `vehicleInfo` | `VehicleInfoFromLookup \| null` | 차량번호 조회로 채워진 제조사·차종·연식·연료·주행거리 등 |

---

## 2. 플로우 요약

### 2.1 카드 내 인라인 플로우 (차량번호로 새로 조회하는 경우)

1. **Step 1 — 차량번호**
   - `vehicleStep === 'input'` 일 때: 차량번호 입력 필드 + **[조회]** 버튼 표시.
   - **[조회]** 클릭 → `setVehicleStep('checking')` → `fetchVehicleByRegistrationNumber(vehicleNumber)` 호출.
   - **성공**: `setVehicleInfo(res.data)`, 주행거리 반영, `setVehicleStep('owner')`.
   - **실패**: `setVehicleCheckError(...)`, `setVehicleStep('input')`.

2. **Step 2 — 소유주 확인**
   - `vehicleStep === 'owner'` (또는 `'confirming'`) 이고 `vehicleInfo` 있을 때: 조회된 차량 요약 + **소유주 이름** 입력 필드 + **[확인]** 버튼 표시.
   - placeholder: `"차량 소유주 이름"`, 안내 문구: `"차량등록증에 기재된 소유주명을 입력해 주세요."`
   - **[확인]** 클릭 시:
     - `ownerName.trim()` 없으면 `setVehicleCheckError('소유주 이름을 입력해 주세요.')` 후 return.
     - 있으면 **현재는** `// TODO: 실제 API 연동 시 소유주 확인 로직 추가` 주석 아래에서 **이름만 입력하면** `setVehicleStep('confirmed')`, `setVehicleCheckError(null)` 로 확정 처리.

3. **확정 후**
   - `vehicleStep === 'confirmed'` 이면 차량 카드에 녹색 체크 + 차량 요약 + **소유주: {ownerName}** 표시.
   - 이 상태에서만 **검증하기**가 동작함.

### 2.2 검증하기 진입 조건 (`handleVerify`)

```ts
if (!vehicleInfo || vehicleStep !== 'confirmed') {
  alert('차량 정보를 먼저 확인해 주세요. 차량번호 조회 후 소유주를 입력해 주세요.');
  return;
}
```

- **차량 정보**가 있고, **차량 확인 단계가 `confirmed`** 일 때만 검증(저장·검증 엔진 호출)으로 진행됩니다.
- 즉, “차량번호 조회 → 소유주 입력 → 확인”까지 끝나야 검증하기가 가능합니다.

### 2.3 저장된 내 차로 검증 (소유주 단계 생략)

- `savedVehicle` 이 있고, `!vehicleInfo && !savedVehicleDismissed && vehicleStep === 'input'` 일 때 **저장된 내 차** 블록 표시.
- **[이 차량으로 검증]** 클릭 시:
  - `setVehicleInfo(savedVehicle)`, `setEstimateMileage(savedVehicle.mileage)`, `setSavedVehicleDismissed(true)`, **`setVehicleStep('confirmed')`**.
- 이 경로에서는 **소유주 입력 없이** 바로 `confirmed`가 되므로 검증하기 가능합니다.

### 2.4 바텀시트 “차량 정보”

- 시트 안에는 **차량등록번호** 입력 + **[차량 정보 불러오기]** + **주행거리** 입력 + **[완료]** 만 있음.
- `handleFetchVehicleByNumber(vehicleNumber)` 만 호출하며, **`vehicleStep`을 변경하지 않음**.
- 따라서 시트에서만 조회하고 완료해도 `vehicleStep`은 `'input'`으로 남고, 검증하기 시 위 알림이 뜹니다.  
  → 검증하려면 카드 쪽에서 **Step 1(조회) → Step 2(소유주 입력 → 확인)** 를 거쳐 `confirmed`로 만들어야 합니다.

## 3. 차량 조회 API (현재는 목업)

- **Server Action**: `fetchVehicleByRegistrationNumber(registrationNumber)`  
  - 위치: `lib/supabase/actions.ts`
- **내부**: `registrationNumber` 정규화(공백·하이픈 제거) 후 `getVehicleLookupByRegistrationNumber(normalized)` 호출.  
  - `lib/supabase/queries.ts` 의 `getVehicleLookupByRegistrationNumber` 가 **`vehicle_lookup_mock`** 테이블에서만 조회.
- **반환**: `{ success, data }` 형태. `data` 에는 `manufacturer`, `model`, `variant`, `year`, `mileage`, `fuelType` 등.  
- **소유주명은 요청/응답에 없음.** 자동차 365 실제 API 연동 시 여기에 `ownerName` 파라미터와 응답 처리 추가 필요.

## 4. 소유주 “인증” 현재 구현 상태

- **UI**: 소유주명 입력 필드 + “차량등록증에 기재된 소유주명을 입력해 주세요” 안내까지 구현됨.
- **검증 로직**:  
  - **실제 API로 소유주 일치 여부 확인하는 코드는 없음.**  
  - `// TODO: 실제 API 연동 시 소유주 확인 로직 추가`  
  - 현재는 **이름만 입력 후 [확인] 누르면** `vehicleStep` 만 `'confirmed'` 로 바꿔서 검증하기가 가능해지는 수준입니다.
- **저장**: `ownerName` 은 화면 표시용으로만 쓰이고, `handleVerify` 안의 `saveVehicle` / `createEstimate` 등에는 넘기지 않습니다. DB에 소유주명을 남기지 않음.

## 5. OCR·초기값과의 관계

- OCR 결과에 `registrationNumber` 가 있으면 (168~182 라인):
  - `vehicleNumber` 는 OCR에서 따로 세팅하지 않고, **차량 정보만** `fetchVehicleByRegistrationNumber(num).then(...)` 으로 비동기 조회.
  - 조회 성공 시: `setVehicleInfo(res.data)`, 주행거리 반영, `setSavedVehicleDismissed(true)` 만 수행. **`setVehicleStep` 호출 없음.**
  - 따라서 OCR으로 차량 정보가 채워져도 `vehicleStep` 은 계속 `'input'` 이라, 사용자는 카드에서 **다시 [조회] 버튼을 눌러** `checking` → `owner` 로 넘어가거나, 차량번호 입력란에 번호가 있으면 [조회]로 Step 2(소유주 입력)까지 진행해야 검증하기가 가능함.

---

## 6. 정리

| 항목 | 내용 |
|------|------|
| **차량 확인 단계** | `input` → `checking` → `owner` → (확인) → `confirmed`. `confirmed` 일 때만 검증하기 가능. |
| **소유주 입력** | 카드 내 Step 2에서만 입력. placeholder·안내 문구까지 구현됨. |
| **소유주 “인증”** | **미구현.** 이름만 넣으면 확정 처리. 자동차 365 API 연동 시 여기에 소유주 확인 로직 추가 필요. |
| **저장된 차량** | “이 차량으로 검증” 시 소유주 단계 없이 `confirmed` 로 설정됨. |
| **바텀시트 차량** | 차량번호·주행거리만 다루고, `vehicleStep` 갱신 없음. 검증하려면 카드에서 소유주 확인까지 해야 함. |
| **차량 조회** | 현재는 `vehicle_lookup_mock` 목업만 사용. 자동차 365 API 연동 시 `registrationNumber` + `ownerName` 전달 및 응답 매핑 필요. |

이 문서는 `app/(main)/verify/review/page.tsx` 및 `lib/supabase/actions.ts`, `lib/supabase/queries.ts` 기준으로 정리했습니다.
