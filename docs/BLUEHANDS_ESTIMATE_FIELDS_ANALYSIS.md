# 블루핸즈 점검·정비명세서(고객용) 기준 적용 가능 항목 분석

## 1. 문서 구조 요약 (블루핸즈 명세서)

- **문서명**: 자동차 점검·정비명세서 (고객용) / 영수증겸용  
- **의뢰자·사업자 정보**: 차량 정보, 정비소 정보, 의뢰/완료/출고 일자  
- **점검·정비 내역**: 무상수리 / 유상수리 구분, 소요부품 + 작업내용  
- **합계**: 부품 합계, 기술료 합계, 소계, 부가세, 총계  
- **기타**: 추가정비동의여부, 부품 구분(A/B/C/D/F), 무상수리 보증 등  

---

## 2. 현재 서비스에서 쓰는 항목

| 구분 | 현재 필드 | 비고 |
|------|-----------|------|
| 견적서 공통 | shopName, totalAmount, requestDate(의뢰일자), vatIncluded, vatAmount | |
| 차량 | vehicleId → Vehicle(manufacturer, model, variant, year, mileage, fuelType) | 별도 차량 관리 |
| 항목 | name, partCost, laborCost, totalCost, category | 항목당 1줄, 부품비/공임비만 |

## 3. 블루핸즈 명세서에 있고 우리에 없는 항목 (적용 검토용)

### 3-1. 견적서·정비소 수준

| 명세서 항목 | 설명 | 적용 시 기대 효과 |
|-------------|------|-------------------|
| **점검·정비완료일자** | 의뢰일자와 별도의 완료일 | 이력·통계, “언제 완료됐는지” 표시 |
| **출고(예정)일자** | 수령 예정일 | 고객 안내, 알림 연동 가능 |
| **정비소 대표자** | 업체 대표자명 | 정비소 상세 정보, 신뢰도 표시 |
| **정비업등록번호** | 사업자/정비업 등록번호 | 정비소 검증, 블루핸즈 매칭 보조 |
| **정비소 주소** | 업체 주소 | 지도/경로, 정비소 검색 품질 향상 |
| **정비책임자** | 담당 정비책임자명 | 항목별 엔지니어와 구분 가능 |
| **추가정비동의여부** | 동의/부동의 | 추후 추가 작업 시 법적·정책 대응 |

### 3-2. 차량 수준 (견적서에 함께 노출되는 정보)

| 명세서 항목 | 설명 | 적용 시 기대 효과 |
|-------------|------|-------------------|
| **차량번호** | 자동차등록번호 | 자동차종합정보 첨부형API 연동 시 키로 사용, “어느 차” 식별 |
| **등록년월일** | 차량 최초등록일 | 현재 `year` 보다 정확한 연식·보증 계산 |

### 3-3. 금액 구조

| 명세서 항목 | 설명 | 적용 시 기대 효과 |
|-------------|------|-------------------|
| **부품 합계** | 유상 부품 금액 합계 | 부품비 vs 공임비 분리 검증·표시 |
| **기술료 합계** | 공임 합계 | 항목별 laborCost 합과 교차 검증 |
| **소계** | 부품+기술료 (VAT 전) | totalAmount = 소계+부가세 일치 여부 검증 |
| **부가세** | VAT 금액 | 이미 vatAmount로 일부 수용 가능 |
| **총계** | 최종 금액 | 현재 totalAmount에 해당 |

→ **부품 합계 / 기술료 합계 / 소계**를 따로 두면, OCR·입력 검증과 “부품비·공임비 적정성” 분석에 유리함.

### 3-4. 항목(라인) 수준

| 명세서 항목 | 설명 | 적용 시 기대 효과 |
|-------------|------|-------------------|
| **무상/유상 구분** | 무상수리 vs 유상수리 | 검증 대상은 보통 “유상”만; 무상은 참고용 |
| **소요부품: 품명** | 부품명 (예: 필터-에어 클리너) | 현재 항목 `name`을 “작업명”으로 두고, 부품명을 별도 필드로 분리 가능 |
| **소요부품: 구분** | A/B/C/D/F (신품/재제조/중고/인증대체/수입) | 부품 품질·가격 비교, 표준표 매칭 시 참고 |
| **소요부품: 수량** | 수량 | 단가×수량 = 금액 검증, 표준 공임표와 조합 시 유리 |
| **소요부품: 단가** | 단가 | partCost = 단가×수량으로 검증 |
| **작업내용: 작업 설명** | 작업 내용 (예: 에어 클리너 필터) | 현재 `name`에 해당; “작업명”으로 명확히 할 수 있음 |
| **작업내용: 엔지니어** | 담당 엔지니어(정비사) | 이력·문의용 (선택) |
| **기술료** | 해당 라인 공임 | 현재 `laborCost`에 해당 |

→ 한 “항목”이 **부품 1개 + 작업 1개**가 아니라 **부품 여러 개 + 작업 1개** 구조일 수 있음.  
  지금 구조는 “항목 = 작업 1개당 1줄, partCost/laborCost 합산”이므로,  
  **부품명/수량/단가**를 넣으려면 `EstimateItem`에 하위 리스트 또는 옵션 필드를 두는 확장이 필요함.

### 3-5. 기타(참고)

| 명세서 항목 | 설명 | 적용 시 기대 효과 |
|-------------|------|-------------------|
| **부품 구분 설명** | A/B/C/D/F 정의 | UI 툴팁·도움말, “신품/인증부품” 등 표시 |
| **무상수리 보증 조건** | 연식·주행 구간별 보증 | 정책/안내용 (검증 로직과는 거리 둬도 됨) |

## 4. 적용 우선순위 제안 (구현 X, 검토용)

1. **금액 구조 분리**  
   견적서 단위로 **부품합계 / 기술료(공임)합계 / 소계 / 부가세 / 총계**를 두면,  
   현재 totalAmount·vatAmount와의 일치 검증, “부품비 vs 공임비” 분석에 바로 쓸 수 있음.

2. **정비소 정보 확장**  
   **주소, 정비업등록번호**를 추가하면 정비소 검색·매칭(예: bluehands_seoul)과 연동하기 좋음.  
   대표자/정비책임자는 선택.

3. **일자 확장**  
   **점검·정비완료일자**, **출고(예정)일자**를 두면 이력·통계와 고객 안내에 활용 가능.

4. **항목: 무상/유상 구분**  
   검증·비교는 “유상”만 하면 되므로, 플래그 하나로 구분해 두는 것이 좋음.

5. **항목: 부품 구분(A/B/C/D/F)**  
   표준 공임표·가격 비교 시 “신품/인증부품” 등 구분이 있으면 유리.  
   항목 확장 시 `partCategory` 같은 필드로 두면 됨.

6. **항목: 수량·단가**  
   partCost = 단가×수량으로 검증하고, 표준표와 단가/공임 비교를 세밀히 하려면  
   `quantity`, `unitPrice`(또는 `partUnitPrice`) 확장을 검토.

7. **차량번호·등록년월일**  
   자동차종합정보 첨부형API 등 외부 연동을 할 때 차량번호가 키가 되므로,  
   견적서에 “차량 식별용”으로만 넣어 두는 방안을 고려.

---

## 5. 정리

- 블루핸즈 명세서에는 **의뢰/완료/출고 일자**, **정비소(대표자, 주소, 등록번호, 책임자)**, **부품합계/기술료합계/소계/부가세/총계**, **무상·유상 구분**, **부품 구분(A~F)**, **수량·단가·엔지니어** 등이 있음.
- 위 항목들을 단계적으로 도입하면,  
  - 견적서 검증 정확도(금액·구성 검증),  
  - 정비소/차량 정보 품질,  
  - 표준 공임표(bluehands_maintenance 등)와의 매칭  
  을 높일 수 있음.
- 실제 스키마·UI 반영은 별도 단계에서 진행하면 됨 (본 문서는 “적용 가능 항목 분석”만 수행).
