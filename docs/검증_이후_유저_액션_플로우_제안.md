# 검증 이후 유저 액션·플로우 제안

현재 서비스는 **견적 입력 → OCR/확인 → 검증 → 검증 결과**에서 끝나고, 결과 화면에서는 **공유하기**만 강하게 노출됩니다.  
검증 이후 "그래서 뭘 하면 돼?"에 대한 답을 주면 완결성과 가치가 커집니다.

---

## 1. 현재 검증 이후 상태

| 화면 | 유저가 할 수 있는 것 |
|------|----------------------|
| 검증 결과 | 요약·항목별 결과 확인, 주행거리 수정·재검증, **공유하기** |
| 항목 상세 (확인필요) | 가이드 문구 확인, "검증 결과로 돌아가기" |
| 이력 상세 | 과거 검증 다시 보기, 공유, 삭제 |

→ **결정(이 견적 받을까? / 다른 곳 갈까?)**, **실행(예약·연락·경로)** 로 이어지는 명시적 플로우는 없음.

---

## 2. 검증 직후 유저가 갖는 자연스러운 질문·욕구

| 질문/욕구 | 설명 |
|-----------|------|
| **이 견적 받을까?** | 적정이면 수용, 확인필요면 정비소에 물어보고 결정 |
| **다른 정비소는 얼마에 해주지?** | 비교 견적을 받고 싶음 |
| **정비소 연락/예약/찾아가기** | 전화, 예약 링크, 지도/경로 |
| **나중에 또 보려면?** | 이미 이력으로 남지만, "이 견적으로 수리 받기로 했어" 같은 상태 표시는 없음 |
| **정비사한테 뭐라고 말하지?** | 확인필요 항목일 때 협상/질문 포인트 (이미 가이드로 제공 중) |
| **다음 정비는 언제?** | 오일 교환 등 주기 정비 리마인드 |

이걸 **액션 가능한 플로우**로 이어주는 게 목표입니다.

---

## 3. 제안 플로우 (우선순위·난이도)

### A. 검증 결과 → **다음 액션 선택** (단기, 추천)

**아이디어**: 검증 결과 하단에 "공유하기"만 두지 말고, **다음에 할 일**을 2~3개 선택지로 제시.

| 액션 | 설명 | 구현 포인트 |
|------|------|--------------|
| **이 견적서로 수리 받기로 했어요** | 사용자가 "결정 완료"를 표시 (선택). 이력에서 "수리 완료/예정" 상태로 보이게 하면 만족도·재방문에 도움. | `verification_results`에 `user_resolution` (accepted / declined / pending) 같은 필드 추가, 결과 화면에서 한 번만 선택 가능하게 |
| **이 정비소 연락/찾아가기** | 전화 걸기, 지도 앱으로 길찾기. 이미 정비소명·주소(OCR) 있고, `national_repair_shops`에 전화번호·위경도 있으면 바로 링크. | 결과/이력 상세에 "전화" "길찾기" 버튼 → `tel:`, 지도 앱 딥링크 |
| **다른 견적도 검증해볼게요** | 새 견적 촬영/입력으로 유도. 검증이 끝이 아니라 "여러 견적 비교" 플로우로 자연스럽게 이어짐. | CTA: "다른 견적서 검증하기" → `/verify` 또는 카메라 |

**UI 예시 (결과 페이지 하단)**  
- 1차: "이 견적으로 수리 받기로 했어요" (체크 또는 버튼)  
- 2차: [전화] [길찾기] (정비소 매칭된 경우만)  
- 3차: [다른 견적서 검증하기]  
- 기존 [공유하기] 유지  

→ **완결성**: "검증 끝 → 결정/연락/비교"까지 한 번에 제시.

---

### B. 검증 결과 → **정비소 정보 강화** (단기)

**아이디어**: 방문한 정비소를 이미 알고 있으니, 그 정비소의 **전화·주소·지도**를 결과/이력에서 바로 쓸 수 있게.

- 견적서의 `shop_name` / `shop_address`로 `national_repair_shops` 매칭이 되면:
  - **전화**: `tel:${phone_number}`
  - **길찾기**: 카카오맵/네이버맵/구글맵 URL (주소 또는 위경도)
- 매칭 안 되면 "주소만 복사" 정도라도 제공.

→ **가치**: 검증만 보는 게 아니라 "그 정비소에 연락/방문"까지 이어짐.

---

### C. **두 번째 견적 비교** (중기)

**아이디어**: 같은 차량·비슷한 정비 항목으로 **여러 견적**을 검증해 두면, "A정비소 vs B정비소" 요약 비교 화면 제공.

- 예: 견적 1 (정비소 A), 견적 2 (정비소 B) → 항목별로 "A 금액 / B 금액 / 참고 평균" 한눈에.
- 전제: 항목이 마스터(`maintenance_job_master`)로 매핑되어 있으면, 견적 간 항목 매칭이 가능.

→ **가치**: "어디 가는 게 나을까?" 결정에 직접 도움.  
→ **구현**: estimate 간 비교 뷰, 동일 차량·비슷 시점 견적 목록, 마스터 매핑 활용.

---

### D. **확인필요 → 정비소 방문 후 피드백** (중기)

**아이디어**: "확인필요"로 나온 항목에 대해, 사용자가 정비소에 문의/수리 후 **간단 피드백**을 남기면 다음 사용자에게 참고가 됨.

- 예: "정비사 설명 들었어요" / "가격 조정됐어요" / "일부 항목 빼기로 했어요" (이미 guide 페이지에 비슷한 체크가 있음)
- 저장 시: 해당 검증 또는 항목에 "사용자 피드백" 플래그/텍스트 저장. (추후 집계 시 "이 항목은 보통 협상 가능" 같은 인사이트로 활용 가능)

→ **가치**: 검증이 1회성으로 끝나지 않고, "실제로 어떻게 됐는지"까지 기록.  
→ **구현**: guide 페이지와 연동해 피드백을 DB에 저장, 이력 상세에서 "내가 남긴 피드백" 표시.

---

### E. **주기 정비 리마인드** (중장기)

**아이디어**: 오일 교환, 에어컨 필터 등 **주기 정비 항목**이 견적에 있으면, "다음 교환 권장 시기"를 계산해 알림/캘린더 제안.

- 예: 오일 교환 시 "다음 권장: 6개월 또는 10,000km 후"
- 전제: 주행거리·검증 일자·항목(마스터 매핑)이 있으면, 항목별 주기(월/주행거리)와 조합해 다음 시점 추정.

→ **가치**: 견적 검증이 "다음 정비 시점"까지 이어지는 경험.  
→ **구현**: 마스터에 주기 메타데이터 추가, 알림/캘린더 연동.

---

### F. **PDF/이미지로 저장** (단기·선택)

**아이디어**: 검증 결과를 **한 장 요약**(견적 요약 + 적정/확인필요 + 핵심 수치)으로 만들어 PDF 또는 이미지로 저장/공유.

- 보험 청구, 정비소 제출, SNS 공유 등에 쓸 수 있음.
- 구현: 결과 데이터로 HTML/Canvas 렌더 후 pdf 또는 이미지 export (클라이언트 라이브러리 활용).

→ **가치**: "검증 결과를 증빙으로 남기고 싶다"는 니즈에 대응.

---

## 4. 우선 적용 제안 (요약)

| 순위 | 플로우 | 기대 효과 | 난이도 |
|------|--------|-----------|--------|
| 1 | **결과 페이지에 "다음 액션" 블록** (수리 받기로 함 / 전화·길찾기 / 다른 견적 검증) | 검증 이후 행동이 명확해지고 완결성↑ | 낮음 |
| 2 | **정비소 전화·길찾기** (매칭된 경우) | 검증 → 연락/방문까지 직결 | 낮음 |
| 3 | **다른 견적서 검증하기** CTA | 재방문·여러 견적 비교 습관 유도 | 낮음 |
| 4 | 사용자 결정 상태 저장 (수리 받기로 함 등) | 이력 가치·재방문 시 "그때 어떻게 했지" 확인 | 중간 |
| 5 | 두 번째 견적 비교 뷰 | 차별화·결정 지원 | 중간 |
| 6 | 확인필요 → 피드백 저장 | 데이터 축적·다음 사용자 가이드 | 중간 |
| 7 | 주기 정비 리마인드 | 롱테일 가치 | 높음 |
| 8 | PDF/이미지 저장 | 니치하지만 명확한 가치 | 중간 |

먼저 **1~3**을 결과 페이지 한 곳에 모아서 "검증 끝 → 이제 이렇게 하세요"를 보여주는 걸 추천합니다. 그다음 정비소 매칭·전화/길찾기 데이터 연결, 그 다음에 사용자 결정 상태 저장과 비교 뷰로 확장하면 됩니다.

---

## 5. 정리

- **현재**: 검증 결과 = "보고 공유"에서 끝.
- **목표**: 검증 결과 = **결정(수리 받을지)** · **실행(연락/길찾기)** · **비교(다른 견적)** 로 이어지는 플로우.
- **첫 단계**: 결과 페이지 하단에 "다음 액션" 블록(수리 받기로 함 / 전화·길찾기 / 다른 견적 검증 + 기존 공유)을 넣고, 정비소가 매칭되면 전화·길찾기 버튼을 노출하는 것부터 적용하면 됩니다.

원하면 1~3번에 대한 화면 와이어프레임(텍스트/목업)이나 API/DB 스키마 변경 포인트만 따로 정리해 줄 수 있습니다.
