# 이미지 품질 판단 수치 및 근거

캔버스(Canvas) API로 **밝기**와 **초점(선명도)**을 계산해, 견적서 촬영 직후 “재촬영 권유” 여부를 결정할 때 쓰는 **구체적 수치**와 **누가/왜 이렇게 정했는지**에 대한 답을 정리한 문서입니다.

---

## 0. Canvas API란? — 어떻게 이미지 품질을 분석할 수 있나

### Canvas API가 뭔가요?

**Canvas API**는 브라우저(JavaScript)에서 **픽셀 단위로 그림을 그리거나, 이미지를 "숫자 배열"로 읽을 수 있게 해주는 기능**입니다.

- 화면에 **사각형 캔버스(도화지)**를 하나 만들고,
- 그 위에 **이미지를 한 번 그린 다음**,
- **"이 캔버스의 각 픽셀마다 R, G, B 값이 뭐야?"**라고 조회할 수 있습니다.

즉, **이미지 = 픽셀들의 R,G,B 숫자 집합**으로 바꿔서, 우리가 그 숫자들을 이용해 계산할 수 있게 해주는 게 Canvas API입니다.

### 이미지는 결국 "숫자들의 격자"

- 모니터/폰 화면의 이미지는 **가로×세로 개수의 픽셀**로 이루어져 있습니다.
- 각 픽셀은 **빨강(R), 초록(G), 파랑(B)** 세 값으로 표현됩니다 (보통 0~255).
- Canvas는 이 **R, G, B 숫자들을 메모리에서 직접 읽고 쓸 수 있게** 해줍니다.

그래서 "이미지가 밝다/어둡다", "경계가 뚜렷하다/흐리다" 같은 것을 **숫자로 계산**할 수 있게 됩니다.

### 우리가 "품질"을 어떻게 분석하는지 (직관적으로)

1. **밝기**
   - 모든 픽셀의 **밝기(휘도)**를 평균냅니다.
   - 숫자가 너무 작으면 → "너무 어두운 사진"
   - 숫자가 너무 크면 → "너무 밝아서 날아간 사진"
   - 이걸 **Canvas로 픽셀값 읽어서 평균** 내는 방식으로 구현합니다.

2. **초점/선명도**
   - **선명한 사진**: 글자와 배경의 **경계에서 픽셀값이 크게 튀어요** (옆 픽셀과 차이가 큼).
   - **흐린 사진**: 경계가 스무스해서 **옆 픽셀과 값이 비슷해요** (차이가 작음).
   - 그래서 **"옆 픽셀과의 밝기 차이(그라디언트)"**를 많이 샘플링해서 평균을 내면,
     - 차이가 크면 → 선명하다고 보고,
     - 차이가 작으면 → 흐리다고 봅니다.
   - 이 "옆 픽셀 값"도 **Canvas로 픽셀 데이터를 읽어서** 계산합니다.

정리하면, **Canvas API = 이미지를 "픽셀 숫자들"로 열어주는 도구**이고, 그 숫자들로 **밝기 평균**과 **픽셀 간 차이(그라디언트)**를 구해서 "밝기 괜찮은지, 초점 괜찮은지"를 판단하는 것입니다.

## 2. 어떻게 계산하는지

### 2.1 전처리

- 이미지를 **긴 변 기준 256px**으로 다운샘플링한 뒤 Canvas에 그려 픽셀 데이터를 읽습니다.
- **4px 간격**으로 샘플링해 성능을 줄입니다.

### 2.2 밝기 (brightness)

- **정의**: 픽셀별 **휘도(Luma)**의 평균.
- **휘도 공식** (표준 가중치):  
  `Luma = 0.2126×R + 0.7152×G + 0.0722×B`  
  (0~255 범위)
- **정규화**:  
  `brightnessNorm = avgBrightness / 255`  
  → **0~1** (0: 매우 어두움, 1: 매우 밝음)

### 2.3 선명도 / 초점 (sharpness)

- **정의**: Laplacian 대신 **인접 픽셀(오른쪽, 아래)과의 휘도 차이(그라디언트)**의 평균.
  - 흐리면 경계가 무뎌져 그라디언트가 작고, 선명하면 커집니다.
- **정규화**:  
  `sharpnessNorm = avgGradient / 64` 를 0~1로 클램프.  
  (코드 주석: “그라디언트 값이 경험적으로 0~64 범위 내에 있을 것으로 가정”)

## 3. 품질 “괜찮은지” 판단하는 구체적 수치

| 항목 | 조건 | 판정 (issues) | 의미 |
|------|------|----------------|------|
| **선명도** | `sharpnessNorm < 0.15` | `blurry` | 사진이 흐려서 글자 인식이 어렵다고 봄 |
| **밝기** | `brightnessNorm < 0.12` | `too_dark` | 평균 휘도가 255 기준 약 30 미만 → 너무 어두움 |
| **밝기** | `brightnessNorm > 0.95` | `too_bright` | 평균 휘도가 255 기준 약 242 초과 → 과다 노출 |

- 위 **세 조건 중 하나라도 만족**하면 “품질 이슈 있음”으로 보고, 재촬영/재선택 유도 UI를 냅니다.
- **수치 요약**:
  - **blurry**: sharpness **0.15 미만**
  - **too_dark**: brightness **0.12 미만**
  - **too_bright**: brightness **0.95 초과**

## 4. 누가, 왜 이 수치로 정했냐고 물어보면

### 4.1 “누가 정했나?”

- **이 서비스(또는 개발팀)**에서, 견적서 OCR 플로우를 구현하면서 **로컬 품질 체크용**으로 정한 값입니다.
- 외부 표준/규격이나 논문에서 가져온 수치가 아니라, **이 프로젝트 내부의 경험적(empirical) 설정**입니다.

### 4.2 “왜 이 수치인가?”

코드 주석에 적힌 대로:

- **“임계값은 경험적 값”**  
  - 실제 견적서 이미지와 OCR 결과를 보면서, “이 정도면 대부분 막아도 되고, 정상 사진은 통과시키자” 수준으로 맞춘 값입니다.
- **“너무 엄격하면 정상 사진도 막히므로 느슨하게 설정”**  
  - 너무 낮게/높게 잡으면:
    - 정상적인 사진까지 재촬영 유도 → 사용자 불편
  - 반대로 너무 느슨하면:
    - 흐리거나 과다/과소 노출 이미지가 그대로 서버/OCR까지 가서 실패 → 재촬영이 늦어짐  
  그래서 **정상 촬영은 통과시키고, 확실히 나쁜 것만 걸러내는 쪽**으로 임계값을 “느슨하게” 두었다고 보면 됩니다.

### 4.3 한 줄로 답할 때

- **“이 서비스에서 견적서 OCR이 잘 되도록, 정상 사진은 통과시키고 확실히 나쁜 이미지만 걸러내려고 경험적으로 정한 값이고, 외부 표준이 아니라 우리가 정한 기준입니다.”**

## 5. 값 조정이 필요할 때

- **조정 위치**: `lib/utils/image.ts` 내 `analyzeImageQuality` 함수 하단의 세 조건문.
- **엄격하게**:  
  - `0.15` → 더 높게 (예: 0.2) → 흐린 사진 더 많이 걸림  
  - `0.12` / `0.95` → 더 좁은 범위 (어두움/밝음 더 민감하게)
- **느슨하게**:  
  - `0.15` → 더 낮게, `0.12` → 더 낮게, `0.95` → 더 높게 하면 “괜찮음”으로 통과하는 비율이 늘어납니다.
- 실제 이미지 샘플로 통과/차단 비율을 보면서 튜닝하는 것을 권장합니다.
