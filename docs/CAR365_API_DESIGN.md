# 자동차 365 API 활용 차량 정보 자동 입력 구상

## 1. 자동차 365 / 공공 API 개요

- **자동차 365** (car365.go.kr): 국토교통부·교통안전공단 등이 제공하는 **자동차 통합이력·종합정보** 서비스
- **공공데이터포털**에서 제공하는 관련 API 예:
  - **자동차종합정보 API**: 차량등록번호 + 소유주명으로 기본정보·제원·이력 조회 (제3자 정보제공 동의 필요 시)
  - **자동차 통합이력 조회**: 검사·정비이력, 의무보험, 체납 등
- **응답 형식**: XML 위주 → 서버에서 파싱 후 JSON으로 변환 필요
- **이용 조건**: 인증키 발급(무료), 이용약관·개인정보 동의 등 확인 필요

---

## 2. 앱에서 필요한 차량 데이터와 API 매핑

| 앱 필드 (Vehicle) | API에서 기대 가능한 항목 | 비고 |
|-------------------|--------------------------|------|
| manufacturer     | 제조사명                 | 매핑 테이블 필요 (현대/기아 등) |
| model            | 차종명, 모델명           | 하이픈/공백 정규화, variant 분리 |
| variant          | 세부 모델(트림)          | 제원 또는 모델명 파싱 |
| year             | 최초등록일 또는 연식     | 연도만 추출 |
| mileage          | 주행거리                 | 정비이력/검사이력에 있을 수 있음 |
| fuelType         | 연료종류                 | 가솔린/디젤/LPG/전기 등 매핑 |

- **주행거리**: “자동차종합정보” 기본 조회에 없을 수 있고, **정비·검사 이력 API**에서 마지막 기록값을 쓰는 방식 검토
- 제조사/차종은 **공공 API 코드값**과 앱의 `manufacturers`·`hyundaiModels` 등 **드롭다운 코드** 매핑 테이블 필요

## 3. 사용자 플로우 제안

### 3-1. 진입 경로

- **A. 차량 등록/수정 화면** (`/vehicle/edit`)
  - 상단에 **“차량번호로 불러오기”** 블록 추가
  - 입력: 차량등록번호(번호판), 필요 시 소유주명(동의 문구와 함께)
  - 조회 성공 시: 제조사·차종·연식·연료 등 폼 자동 채움, 주행거리만 사용자 확인/수정
  - 조회 실패/미동의 시: 기존처럼 수동 입력 유지

- **B. 견적서 확인 화면** (선택)
  - “차량 정보” 카드에서 “차량번호로 불러오기” 링크 → 같은 조회 플로우 후 결과만 반영
  - 검증 정확도를 위해 “차량 정보가 정확한지 확인해 주세요” 문구 유지

### 3-2. 단계별 플로우 (A 기준)

1. 사용자가 **차량등록번호** 입력 (예: 12가 3456, 띄어쓰기/하이픈 제거 후 전송)
2. (API가 소유주명을 요구할 경우) **소유주명** 입력 + “정보 조회를 위한 이용 동의” 체크
3. **조회** 버튼 → 서버에서 공공 API 호출
4. **성공**: 응답 매핑 → 폼에 manufacturer, model, variant, year, fuelType 반영, mileage는 “확인/수정” 안내
5. **실패**: “조회되지 않았어요. 아래에서 직접 입력해 주세요” + 기존 수동 입력 폼
6. 사용자가 주행거리 등 보완 후 **저장** (기존 `saveVehicle` 플로우 유지)

## 4. 기술적 접근

### 4-1. API 키·호출 위치

- **서버에서만** 공공 API 호출 (API 키 노출 방지)
  - Next.js **Route Handler** (`/api/vehicle/lookup` 등) 또는 **Server Action**에서 호출
- 요청 파라미터: `registrationNumber`(차량등록번호), 필요 시 `ownerName`(소유주명)
- 응답: XML → 서버에서 파싱 후 **JSON**으로 변환해 클라이언트에 전달

### 4-2. 응답 → Vehicle 매핑

- 공공 API 응답 필드명/코드값 문서 확인 후:
  - 제조사 코드 → `manufacturer` (현대, 기아 등)
  - 차종/모델명 → `model`, `variant` (규칙 또는 키워드로 분리)
  - 최초등록일 → `year`
  - 연료 → `fuelType`
  - 주행거리 → 이력 API 있으면 사용, 없으면 `0` 또는 null로 두고 “직접 입력” 유도
- 매핑 실패 시 해당 필드만 비우고, 나머지만 채우고 “일부만 조회됐어요” 안내

### 4-3. 에러·제한 처리

- **API 오류**: 타임아웃, 5xx, 4xx → “일시적인 오류입니다. 나중에 다시 시도하거나 직접 입력해 주세요”
- **조회 없음**: 0건 → “등록된 차량이 없거나 조회 권한이 없어요. 직접 입력해 주세요”
- **요청 제한**: 공공 API 일일/분당 제한 있으면, 서버에서 캐시(같은 번호 짧은 시간 재조회 방지) 또는 “잠시 후 다시 시도” 메시지

### 4-4. 개인정보·동의

- 차량번호·소유주명은 **개인정보**이므로:
  - 조회 전 “차량 정보 조회를 위해 국토교통부 등에 전달·조회됩니다” 안내
  - 소유주명 필요 시 “본인 차량 확인을 위해 소유주명을 입력해 주세요” + 동의 체크
  - 입력값은 **조회용으로만** 사용하고, 저장 시에는 차량 정보(제조사, 차종, 연식 등)만 저장 (번호·소유주명은 저장하지 않는 설계 권장)

## 5. 구현 시 우선순위 제안

| 순서 | 내용 | 비고 |
|------|------|------|
| 1 | 공공데이터포털에서 실제 사용할 API 선정 및 가입·키 발급 | 자동차종합정보 vs 통합이력 등 |
| 2 | API 명세(요청/응답 XML) 확인 및 테스트 호출 (Postman 등) | 필드명·코드값 확보 |
| 3 | Next.js 서버 API Route (또는 Server Action)에서 호출 + XML→JSON 변환 | 키는 env에만 |
| 4 | 응답 → Vehicle 필드 매핑 로직 (제조사/차종/연료 코드 테이블) | 주행거리 없을 때 대비 |
| 5 | `/vehicle/edit`에 “차량번호로 불러오기” UI + 호출 + 폼 반영 | 실패 시 수동 입력 유지 |
| 6 | (선택) 견적서 확인 화면에서도 동일 조회 노출 | 동일 API/매핑 재사용 |

## 6. 리스크·대안

- **API 변경·중단**: 공공 API는 명세 변경·일시 중단 가능 → “차량번호로 불러오기”는 **보조 수단**으로 두고, 수동 입력은 항상 가능하게 유지
- **주행거리 미제공**: 많은 API가 실시간 주행거리를 주지 않음 → “연식·차종만 자동 입력, 주행거리는 직접 입력”으로 UX 설계
- **동의/소유주명**: 본인 차량만 조회 가능한 API라면, “본인 명의 차량만 조회 가능합니다” 안내로 기대치 조정

이 구상을 기준으로, 실제 사용할 API가 정해지면 요청/응답 샘플을 넣어 매핑 규칙과 에러 케이스를 더 구체화하면 됩니다.
