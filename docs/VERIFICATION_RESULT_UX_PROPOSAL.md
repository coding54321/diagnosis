# 검증 결과 화면 UI/UX 구상: 부품비·공임비 표시

## 1. 배경: 견적서 데이터의 두 가지 형태

| 형태 | 설명 | OCR 결과 예 |
|------|------|-------------|
| **행 분리형** | 부품 계·공임 칸이 따로 있어, 한 행은 부품만 또는 공임만 | 부품 항목 → partCost만, laborCost=0 / 공임 항목 → laborCost만, partCost=0 |
| **한 줄 복합형** | 한 작업에 부품 계 + 공임이 같이 있음 (공임나라 등) | partCost > 0, laborCost > 0, totalCost = 부품+공임 |

→ UI는 **두 경우 모두** 자연스럽게 보여주고, “부품이 비싼지 / 공임이 비싼지”를 **항목 단위**와 **전체 요약**에서 모두 드러나게 하는 것이 목표.

---

## 2. 제안: “탭 분리”보다 “한 화면 + 분해 표시”

### 2.1 탭/토글로 부품·공임을 나누는 방식의 한계

- **행 분리형**  
  부품 전용 행 / 공임 전용 행이 이미 있으므로, “부품 탭 / 공임 탭”은 현재 **필터(전체/부품/공임/확인필요)** 와 역할이 겹침.
- **한 줄 복합형**  
  한 항목에 부품+공임이 같이 있을 때:
  - 두 탭에 모두 노출 → 중복·혼란
  - 한쪽 탭에만 노출 → “이 항목은 부품이 문제인데 공임 탭에만 있다” 같은 비직관 발생.

→ **“부품만 보기 / 공임만 보기”를 메인 전환 축으로 두기보다**,  
**한 리스트에서 각 항목마다 부품비·공임비를 분해해서 보여주는 방식**이 더 유저친화적.

### 2.2 추천: “요약 + 항목별 부품/공임 분해”

- **상단 요약 (현재 유지·보강)**  
  - 총액, 부품비 합계 / 공임비 합계, 비율 바  
  - **기준 대비:** 부품 합계 vs WPC/Reference 기대치, 공임 합계 vs FRT×요율 기대치  
  → “전체적으로 부품이 높은지, 공임이 높은지” 한눈에 파악.

- **항목 리스트 (카드 개선)**  
  - 각 카드에 **한 항목 안에서** 부품비·공임비를 나눠 표시:
    - `part` 항목: “부품 90,000원” + (기준 있으면) “기준 대비 +20%” 등
    - `labor` 항목: “공임 80,000원” + “적정” / “기준 대비 +15%” 등
    - `combined` 항목: 두 줄  
      - “부품 90,000원 (기준 대비 +20%)”  
      - “공임 80,000원 (적정)”  
  - 0원인 쪽은 표기 생략 또는 “부품 없음” / “공임 없음” 등 최소 표시.

→ 탭 없이도 **항목별로 “부품이 비싼지, 공임이 비싼지”** 직관적으로 보이고,  
행 분리형(부품만/공임만 행)과 한 줄 복합형(부품+공임 한 행) 모두 동일한 패턴으로 처리 가능.

## 3. 정비소 유형별 메시지·가이드 (현재 + 보강)

### 3.1 블루핸즈/오토큐

- **부품:** WPC(현대모비스) 기준가로 “정확한 기준가” 표시.  
  - **과다 시:** “이 부품이 사용되었을 가능성이 있습니다. 가격이 다르다면 사용 부품번호를 정비사에게 확인해보세요.” 등 가이드.
- **공임:** FRT×권장 요율로 기대 공임 제시, ±범위 내면 적정.

### 3.2 그 외 정비소 (Reference Range + FRT)

- **부품:**  
  - WPC를 **상한/참고**로 두고,  
    - 실제 > 기준 → “순정 권장가보다 높게 책정됨. 마진·유통비 확인 필요.”  
    - 실제 ≈ 기준 → “순정 수준으로 책정됨.”  
    - 실제 < 기준 → “순정 대비 저렴. 애프터마켓·재생 부품 가능성 안내.”
- **공임:**  
  - FRT × 정비소 유형별 시간당 공임(공임나라 정찰, 일반 카센터 구간 등)으로 기대 공임 산출.  
  - ±15% 이내 적정, 초과 시 “추가 작업(고착, 분해 등) 여부를 정비사에게 물어보세요” 유도.

### 3.3 “기술료가 여러 항목 합쳐진 경우” 안내 (추가 고려)

- **현재:** 항목 단위로 partCost/laborCost 저장 → “A항목 공임 0, B항목 공임 0, C항목 공임 10만”처럼 되어 있으면, C에 10만이 몰려 있을 수 있음.
- **추가 시:**  
  - 공임이 0인 항목이 많고, 소수 항목에만 큰 공임이 있을 때  
    → “일부 항목에 여러 작업의 공임이 합쳐져 있을 수 있어요. 정비사에게 작업별 공임을 여쭤보시면 도움이 됩니다.” 같은 **문맥 안내**를 요약 영역 또는 항목 리스트 상단에 노출.

## 4. 현재 시스템과의 매핑

| 구상 요소 | 현재 구현 | 제안 |
|-----------|-----------|------|
| 상단 요약 | VerificationSummary: 총액, 부품/공임 비율 바, 기준 대비 % | 유지. 필요 시 “부품 합계 적정/주의”, “공임 합계 적정/주의” 문구 추가 |
| 항목 필터 | 전체/부품/공임/확인필요 칩 | 유지. “부품만/공임만” 탭은 도입하지 않음 |
| 항목 카드 | EstimateCard: totalCost, costType 태그, 평균 대비 %, 가이드 | **카드에 부품비/공임비 분해 라인 추가** (part/labor/combined 모두 동일 패턴) |
| 항목 상세 | [itemId] 페이지: 부품비/공임비 블록, 시장 평균 | 유지. 무상수리·가이드 문구는 이미 반영됨 |
| 검증 로직 | verifyItem: WPC/FRT, shopType별 판정, guide 생성 | 블루핸즈/오토큐 “과다 시” 문구만 가이드 메시지에 명시적으로 추가 가능 |

---

## 5. 구현 시 우선순위 제안

1. **EstimateCard에 부품/공임 분해 표시**  
   - `breakdown.partCost.user` / `breakdown.laborCost.user` 사용.  
   - 0원이 아닌 것만 라인 표시.  
   - combined일 때 두 줄, part만/ labor만일 때 한 줄.
2. **VerificationSummary**  
   - “부품 합계: 기준 대비 +20%” / “공임 합계: 적정”처럼 **문장형 한 줄** 추가 검토 (선택).
3. **가이드 문구**  
   - 블루핸즈/오토큐 부품 과다 시: “사용 부품 확인 요청” 문구를 guide-messages에 추가.
4. **기술료 합산 안내**  
   - 공임 0인 항목 비율이 높고, 소수 항목에 공임이 집중된 경우 안내 문구 노출 (추후).

## 6. 더미 데이터 (Supabase)

검증·견적 플로우가 모두 동작하도록 Supabase에 더미 데이터를 넣어 두었습니다.

- **차량:** 현대 코나 OS (기존 `vehicles` 1건 사용)
- **견적 ID:** `47c784f9-9f3f-4b72-9d5e-af9fd209a9b5`
- **정비소:** 블루핸즈 강남점 (`shop_type`: bluehands), 총액 143,000원
- **항목 4종:**
  - **무상수리:** 엔진오일 교환 (무상) — 부품 0, 공임 0 → 무상수리 처리·비교 제외
  - **부품만:** 에어클리너 필터 — 부품 18,000원, 공임 0
  - **공임만:** 브레이크 오일 교환 — 부품 0, 공임 25,000원
  - **혼합:** 전륜 브레이크 패드 — 부품 45,000원, 공임 55,000원 (총 100,000원)

**결과 화면 테스트:**  
브라우저에서 `/verify/result` 접속 전에 `sessionStorage`에 아래를 설정한 뒤 새로고침하면 해당 견적의 검증 결과가 로드됩니다.

```js
sessionStorage.setItem('currentEstimateId', '47c784f9-9f3f-4b72-9d5e-af9fd209a9b5');
sessionStorage.setItem('currentShopName', '블루핸즈 강남점');
sessionStorage.setItem('currentVehicleRegistration', ''); // 선택
```

이 구상대로 적용하면 “부품비/공임비를 탭으로 나눌지” 고민 없이, **한 화면에서 항목별·전체 모두 분해되어 보이고**, 견적서가 부품 행/공임 행으로만 나오든 한 줄에 복합이든 동일한 UX로 처리할 수 있습니다.
