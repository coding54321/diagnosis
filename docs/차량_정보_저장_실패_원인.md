# 차량 정보 저장 실패 (견적 검증하기 오류) 원인

## 증상

- **견적 검증하기** 버튼 클릭 시 `Error: 차량 정보 저장 실패` 발생
- `handleVerify` 내부에서 `saveVehicle` 호출 후 `vehicleResult.success`는 true인데 `vehicleResult.data`가 null인 경우 throw

## 원인

1. **`upsertVehicle`이 실패해도 null만 반환**
   - Supabase `insert`/`update` 실패 시 `upsertVehicle`이 `null`만 반환하고, `saveVehicle`은 이를 검사하지 않고 `{ success: true, data: null }`을 반환함
   - 클라이언트는 `!vehicleResult.data`일 때 "차량 정보 저장 실패"로 throw

2. **실제 DB 실패 원인 (가능성)**
   - **RLS 정책**: `vehicles` 테이블에 `user_id = auth.uid()` 등만 허용하는 정책이면, 비로그인(익명) 시 `user_id: null` insert가 거부될 수 있음
   - **제약 조건**: NOT NULL, UNIQUE 등 위반
   - **네트워크/권한**: Supabase 프로젝트 설정·키 문제

## 수정 사항 (적용됨)

1. **`lib/supabase/queries.ts` – `upsertVehicle`**
   - 반환 타입을 `Vehicle | null` → `{ data: Vehicle | null; error: string | null }`로 변경
   - 실패 시 Supabase `error.message`를 그대로 반환해 원인 전달
   - 익명 사용자 시 `getVehicle('anonymous')` 대신 `getVehicle('')` 호출 (기존과 동일하게 insert 분기)

2. **`lib/supabase/actions.ts` – `saveVehicle`**
   - `upsertVehicle` 반환값의 `data`/`error`를 검사
   - `error`가 있거나 `data`가 null이면 `{ success: false, error: 메시지 }` 반환 (실제 DB 에러 메시지 전달)
   - 클라이언트에서 동일한 alert/에러 처리로 더 구체적인 메시지 노출 가능

3. **카메라 페이지**
   - 버튼 문구: "견적서 이미지 분석하기" → "분석하기"로 변경

## 비로그인(익명) 사용자 견적 검증 허용 (적용됨)

마이그레이션 `allow_anonymous_vehicle_estimate_verification` 적용으로 다음 RLS 정책이 수정되었습니다.

- **vehicles**: INSERT/UPDATE 시 `(auth.uid() = user_id) OR (user_id IS NULL)` 허용
- **estimate_items**: INSERT/SELECT/UPDATE/DELETE 시 부모 `estimates.user_id IS NULL` 또는 본인 소유일 때 허용
- **item_verifications**: INSERT/SELECT 시 부모 `verification_results.user_id IS NULL` 또는 본인 소유일 때 허용

`estimates`, `verification_results`는 이미 INSERT 시 `user_id IS NULL`을 허용하고 있었습니다.
