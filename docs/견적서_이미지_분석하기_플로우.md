# 견적서 이미지 '분석하기' 플로우 전체 정리

사용자가 견적서 이미지를 넣고 **분석하기**를 눌렀을 때 발생하는 일을 코드 기준으로 정리한 문서입니다.

---

## 1. 진입점: 카메라 페이지 (`/verify/camera`)

### 1.1 분석하기 버튼

- **위치**: 촬영된 이미지가 있을 때 하단 컨트롤의 **「분석하기」** 버튼
- **핸들러**: `handleUsePhoto` (클릭 시 실행)

### 1.2 `handleUsePhoto` 동작 (카메라 페이지)

1. **입력 검증**  
   - `capturedImage`가 없으면 `return` (아무 동작 없음)

2. **로컬 이미지 품질 체크 (선택)**  
   - `analyzeImageQuality(capturedImage)` 호출 (클라이언트, `lib/utils/image.ts`)
   - **내부 동작**:
     - 이미지를 256px 기준으로 다운샘플링 후 `<canvas>`로 그리기
     - 픽셀 데이터로 **밝기(brightness)**, **그라디언트 기반 샤프니스(sharpness)** 계산
     - 이슈 판정:
       - `sharpness < 0.15` → `blurry`
       - `brightness < 0.12` → `too_dark`
       - `brightness > 0.95` → `too_bright`
   - **이슈가 하나라도 있으면**  
     → `setQualityWarning({ issues, sharpness, brightness })` 설정 후 **함수 종료** (재촬영 유도 UI 표시)
   - 예외 발생 시: `console.warn`만 하고 아래 단계로 진행

3. **세션 저장 및 페이지 이동**  
   - `sessionStorage.setItem('capturedEstimateImage', capturedImage)` — base64 이미지 저장  
   - `sessionStorage.setItem('pendingOcr', '1')` — review 페이지에서 OCR 실행할 플래그  
   - `router.push('/verify/review')` — **리뷰 페이지로 이동** (이 시점에서는 OCR 호출 없음)

## 2. 리뷰 페이지 마운트 (`/verify/review`)

### 2.1 초기 로드 시 useEffect

- **읽는 값**: `sessionStorage`  
  - `capturedEstimateImage` (이미지 base64)  
  - `ocrResult` (이미 있으면 이전 경로에서 저장된 값)  
  - `pendingOcr` (카메라에서 이미지만 저장하고 왔는지 여부)

- **이미지 있음 + `pendingOcr` 있음**인 경우:
  1. `sessionStorage.removeItem('pendingOcr')`
  2. `setIsOcrLoading(true)`, `setOcrError(null)`
  3. **서버 액션** `analyzeEstimateImage(image)` 호출 (아래 3절)
  4. **성공 시**:
     - `sessionStorage.setItem('ocrResult', JSON.stringify(ocrResult))`
     - `applyOcrResultToState(ocrResult)` (아래 4절)
     - `setWizardStep(2)` → Step 2(정비 정보 확인)로 전환
  5. **실패 시** (`!ocrResult.success`):
     - `ocrResult.status`에 따라 `setOcrError`:
       - `NOT_ESTIMATE`: "견적서가 아닌 것으로 보입니다..."
       - `POOR_QUALITY`: "이미지 품질이 낮아 인식이 어려울 수 있습니다."
       - 기타: `ocrResult.error` 또는 기본 메시지
  6. **예외 시** (catch):  
     "이미지 분석 중 오류가 발생했습니다. 직접 입력으로 진행해주세요." 로 `setOcrError`
  7. **finally**: `setIsOcrLoading(false)`

- **동시에** 저장된 차량 정보 로드: `loadSavedVehicle()` → `fetchVehicle()` (로그인 사용자용)

## 3. 서버 쪽 이미지 분석: `analyzeEstimateImage` (`lib/openai/vision.ts`)

- **입력**: base64 이미지 문자열 (또는 URL)
- **출력**: `OCRResult` (성공 시 `{ success: true, data: {...} }`, 실패 시 `{ success: false, status?, error }`)

### 3.1 실행 순서

1. **OpenAI API 키**  
   - `process.env.OPENAI_API_KEY` 없으면 즉시 `{ success: false, error: '...' }` 반환

2. **Upstage OCR 시도** (`process.env.UPSTAGE_API_KEY` 있을 때만)  
   - `parseDocumentWithUpstage(imageUrl)` 로 이미지에서 **텍스트 추출**
   - 성공 + 비어 있지 않은 텍스트 → **텍스트만** 가지고 `analyzeEstimateFromText(upstageResult.text)` 호출 후 그 결과 반환 (이미지 직접 분석 생략)
   - 실패 또는 빈 텍스트 → 아래 Vision 폴백으로 진행

3. **폴백: OpenAI Vision (GPT-4o)**  
   - `openai.chat.completions.create`:
     - **system**: 한국 자동차 정비 문서(견적서/명세서) 분석용 프롬프트  
       - 문서 유형 판별, 정비소명·주소·날짜·차량번호·차종·주행거리·항목 배열·총액·부가세·카테고리 등 추출 규칙  
       - `name`(원문) / `normalizedName`(블루핸즈 표준 작업명) 구분  
       - JSON 형식 지정
     - **user**: 이미지 + "이 견적서/명세서 이미지를 분석해주세요..." 텍스트
   - `response_format: { type: 'json_object' }`, `max_tokens: 4000`
   - 응답 content가 비어 있으면 → `{ success: false, error: '...' }`

4. **응답 JSON 검증 및 실패 케이스**  
   - `isEstimate === false` 이고 유효한 `items`도 없음 → `NOT_ESTIMATE`  
   - `confidence < 0.3` 이고 유효한 items 없음 → `NOT_ESTIMATE`  
   - `quality.imageQuality < 0.5` → `POOR_QUALITY`  
   - 위에 해당하지 않으면 성공 처리 후 **항목 정규화** `normalizeOCRItems(parsed.items)` 적용

5. **성공 시 반환 구조**  
   - `data`: `shopName`, `shopAddress`, `date`, `registrationNumber`, `vehicleModel`, `mileage`, `items[]`, `totalAmount`, `vatIncluded`, `vatAmount`  
   - `status`: `'PARTIAL'` | `'COMPLETE'` (필드 누락 여부)

## 4. OCR 결과를 화면/다음 단계에 반영: `applyOcrResultToState`

- **호출 시점**: review 페이지 mount 시 `pendingOcr` 분기에서 OCR 성공 시, 또는 이미 `ocrResult`가 sessionStorage에 있을 때
- **역할**: `ocrResult.data`를 review 페이지의 React state와 부가 API 호출로 반영

### 4.1 정비소 매칭

- `data.shopName` 또는 `data.shopAddress`가 있으면:
  - `setShopLookupLoading(true)`
  - **GET** `/api/shops?q={ocrShopName}&address={ocrShopAddress}` 호출
    - **API 동작** (`app/api/shops/route.ts`):
      - `address`가 있으면 `searchNationalRepairShopsByAddress(address)` (전국자동차정비업체 표준데이터)
      - `q`(정비소명)가 있으면 주소 결과와 정비소명 키워드로 재랭킹 또는 `searchNationalRepairShops(q)` (이름 검색)
      - 블루핸즈 서울 CSV 등과 연동해 BluehandsShop 형태로 반환
    - 응답 `shops[0].업체명`을 `setShopName(...)` 으로 설정
  - `setShopLookupLoading(false)` (finally)

### 4.2 의뢰일(방문일)

- `data.date`가 있으면:
  - 미래일이면 오늘 날짜로 보정
  - `setRequestDate(dateToSet)`
  - 데이트 피커용 `setTempYear`, `setTempMonth`, `setTempDay` 설정

### 4.3 정비 항목

- `data.items`가 있으면:
  - 각 항목을 `id: 'ocr-item-{index}'`, `name`, `normalizedName`, `partCost`, `laborCost`, `totalCost`, `category` 형태로 변환
  - `setItems(...)` 로 견적 목록 state 설정

### 4.4 차량 관련

- `data.registrationNumber` → `setVehicleNumber(...)`
- `data.vehicleModel` → `setOcrVehicleModel(...)`
- `data.mileage` → `setOcrMileage(...)`, `setEstimateMileage(...)`
- `data.vatIncluded` / `data.vatAmount` → `setVatIncluded`, `setVatAmount`

### 4.5 차량번호로 차량 정보 조회

- `data.registrationNumber`가 있으면:
  - **Server Action** `fetchVehicleByRegistrationNumber(num)` 호출  
    - 내부: `getVehicleLookupByRegistrationNumber(normalized)` (Supabase `vehicle_lookup_mock` 또는 연동 API 조회)
  - 성공 시:
    - `setVehicleInfo(res.data)` (제조사, 모델, 연식, 주행거리 등)
    - OCR 주행거리 우선, 없으면 조회 결과 주행거리로 `setEstimateMileage`
    - `setSavedVehicleDismissed(true)` (저장된 내 차 선택 UI 숨김)

## 5. 화면 표시 (리뷰 Step 1)

- **OCR 대기 중** (`isOcrLoading === true`):  
  - "견적서가 입력되었어요" + "잠시만 기다려주세요..." + 스피너
- **OCR 실패** (`ocrError` 설정됨):  
  - "인식에 실패했어요" + `ocrError.message` + [다시 촬영하기] / [직접 입력하기] 버튼
- **OCR 성공**:  
  - `setWizardStep(2)` 로 Step 2(날짜/정비소 확인)로 자동 전환되므로, 사용자는 곧바로 Step 2 화면을 보게 됨

## 6. 요약 플로우 다이어그램

```
[분석하기 클릭]
       │
       ▼
 handleUsePhoto
       │
       ├─ (선택) analyzeImageQuality → 이슈 있으면 qualityWarning 표시 후 종료
       │
       ├─ sessionStorage: capturedEstimateImage, pendingOcr
       │
       └─ router.push('/verify/review')
              │
              ▼
       [Review 페이지 마운트]
              │
              ├─ pendingOcr 있음 → setIsOcrLoading(true)
              │        │
              │        ▼
              │   analyzeEstimateImage(image)  [Server]
              │        │
              │        ├─ UPSTAGE_API_KEY 있으면 Upstage OCR → 텍스트 → analyzeEstimateFromText
              │        └─ 없거나 실패 → OpenAI Vision (gpt-4o) 이미지 분석 → JSON 파싱·검증
              │        │
              │        ├─ 성공 → sessionStorage.setItem('ocrResult'), applyOcrResultToState, setWizardStep(2)
              │        └─ 실패 → setOcrError(...)
              │        │
              │        └─ finally: setIsOcrLoading(false)
              │
              └─ applyOcrResultToState 내부:
                     ├─ /api/shops (정비소명·주소) → setShopName
                     ├─ setRequestDate, setItems, setVehicleNumber, setOcrVehicleModel, setEstimateMileage, setVat*
                     └─ fetchVehicleByRegistrationNumber(차량번호) → setVehicleInfo, setEstimateMileage
```

## 7. 관련 파일 목록

| 구분 | 파일 |
|------|------|
| 카메라 페이지 | `app/(main)/verify/camera/page.tsx` (handleUsePhoto, 분석하기 버튼) |
| 리뷰 페이지 | `app/(main)/verify/review/page.tsx` (mount useEffect, applyOcrResultToState, Step 1 UI) |
| 이미지 품질 | `lib/utils/image.ts` (analyzeImageQuality) |
| OCR (서버) | `lib/openai/vision.ts` (analyzeEstimateImage, analyzeEstimateFromText) |
| Upstage OCR | `lib/upstage/document-ocr.ts` (parseDocumentWithUpstage) |
| 정비소 API | `app/api/shops/route.ts` (GET /api/shops) |
| 정비소 검색 로직 | `lib/data/national-repair-shops.ts`, `lib/data/bluehands-seoul.ts` |
| 차량 조회 | `lib/supabase/actions.ts` (fetchVehicleByRegistrationNumber), `lib/supabase/queries.ts` (getVehicleLookupByRegistrationNumber) |

이 문서는 위 플로우가 구현된 코드 기준으로 작성되었으며, 이후 수정 시 함께 갱신하는 것을 권장합니다.
