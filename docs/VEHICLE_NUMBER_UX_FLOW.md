# 차량번호 기반 차량 정보 자동 채움 UX 플로우

유저가 차량번호만 입력해도 제조사·차종·연식·연료 등을 직접 넣지 않도록, 견적 촬영 플로우와 내 차 관리 플로우에 차량번호 인식·조회를 어떻게 녹일지 정리한 문서입니다.

---

## 1. 전제

- **차량번호 = 차량등록번호(번호판)** 로, 자동차종합정보 첨부형API(또는 목업) 조회 키로 사용한다.
- 조회 시 **제조사, 차종, 연식, 연료** 등이 자동으로 채워지고, **주행거리**는 API에 없을 수 있으므로 사용자 입력/수정으로 둔다.
- "검증"이란 여기서 **차량번호로 조회한 결과가 내 차가 맞는지 확인·수정하는 단계**를 말한다.

---

## 2. 견적서에 차량번호가 있는 경우

### 2.1 흐름 요약

```
촬영/이미지 등록
    → AI 인식 (견적 항목 + 차량번호 추출)
    → Review 화면 진입
    → "차량" 카드에 차량번호 표시 + [차량 정보 불러오기] 버튼
    → 사용자가 [차량 정보 불러오기] 탭
    → API(또는 목업) 조회
    → 조회 결과로 제조사·차종·연식·연료 자동 채움, 주행거리만 입력/수정 유도
    → 사용자 확인 후 [검증하기]
```

### 2.2 상세

1. **촬영/이미지 등록**
   - 기존과 동일. 견적서 촬영 또는 앨범에서 선택.

2. **AI 인식**
   - 멀티모달 AI가 **견적 항목(정비소명, 항목·금액)** 과 **차량번호**를 함께 추출한다.
   - 차량번호가 인식되면 `recognizedRegistrationNumber` 같은 필드로 다음 단계에 넘긴다.

3. **Review 화면 (견적서 확인)**
   - **의뢰일자, 정비소, 차량, VAT, 정비 항목** 구조는 유지.
   - **차량 블록**:
     - **차량번호가 인식된 경우**:  
       - 1행: 인식된 차량번호 표시 (예: `12가3456`) + 수정 가능(탭 시 바텀시트에서 편집).  
       - 2행: **"차량 정보 불러오기"** 버튼 (또는 "이 번호로 정보 조회").  
       - 3행(조회 전): "차량번호를 입력했거나 인식했어요. 위 버튼을 누르면 제조사·차종 등이 자동으로 채워져요." 안내.  
       - 3행(조회 후): 제조사·차종·연식·연료·주행거리 표시 (주행거리만 수정 가능하거나, 전체 수정 가능).
     - 사용자가 **차량번호를 먼저 수정**한 뒤 [차량 정보 불러오기]를 눌러도 된다.

4. **"차량 정보 불러오기" 동작 (검증 시점)**
   - **언제 API 호출할지**: 버튼을 **눌렀을 때** 진행하는 것을 권장한다.  
     - 이미지 분석 직후 자동 조회는, 인식 오류(잘못된 번호) 시 불필요한 API 호출과 잘못된 정보 채움으로 이어질 수 있음.  
     - 사용자가 **번호를 확인·수정한 뒤** "불러오기"를 누르면, 의도한 번호로 한 번만 조회할 수 있어 자연스럽다.
   - **동작**:  
     - 현재 화면의 차량번호(인식값 또는 사용자 수정값)로 `fetchVehicleByRegistrationNumber(registrationNumber)` 호출.  
     - 성공 시: 제조사·차종·연식·연료를 폼/상태에 반영하고, 주행거리는 0 또는 비워두고 "주행거리만 입력해 주세요" 안내.  
     - 실패 시: "등록된 차량이 없어요. 아래에서 제조사·차종 등을 직접 입력해 주세요." + 기존 수동 입력 UI 유지.

5. **검증(확인)**
   - 조회 결과를 **미리 보기**로 보여준 뒤, "이 차량이 맞나요?" 확인.  
   - 맞으면 그대로 두고, 틀리면 차량번호 수정 후 다시 [차량 정보 불러오기] 또는 수동 입력.

6. **검증하기**
   - 기존처럼 `saveVehicle` → `createEstimate` → 검증 엔진 → 결과 저장 → 결과 화면.  
   - 이때 쓰는 차량 정보는 **조회로 채워진 값 + 사용자가 보정한 주행거리**이다.

### 2.3 UI 배치 (Review 화면)

- **차량** 카드 내부 예시:
  - 라벨: "차량"
  - 1) 차량번호: `12가3456` (탭 시 수정) + 우측 [차량 정보 불러오기]
  - 2) 조회 전: 안내 문구 한 줄.
  - 3) 조회 후: `현대 아반떼 · 2020년식 · 가솔린` + 주행거리 입력란(또는 "주행거리 0km → 확인해 주세요").
- 바텀시트 "차량 정보"에서 **차량번호, 주행거리** 수정 가능하게 두고, "차량 정보 불러오기"는 카드 위 버튼 한 번으로 동작하게 두면 된다.

## 3. 견적서에 차량번호가 없는 경우

### 3.1 흐름 요약

```
촬영/이미지 등록
    → AI 인식 (견적 항목만 추출, 차량번호 없음)
    → Review 화면 진입
    → "차량" 카드에 차량번호 입력란 + [차량 정보 불러오기]
    → 사용자가 차량번호 입력 후 [차량 정보 불러오기] 탭
    → 이후는 "있는 경우"와 동일 (조회 → 자동 채움 → 주행거리 입력/수정 → 검증하기)
```

### 3.2 상세

1. **AI 인식**
   - 견적 항목·정비소·금액만 추출하고, 차량번호 필드는 비운다.

2. **Review 화면**
   - **차량** 카드:
     - 1행: **차량번호 입력란** (플레이스홀더: "예: 12가3456") + [차량 정보 불러오기].  
     - 2행: "차량번호를 입력한 뒤 버튼을 누르면 제조사·차종 등이 자동으로 채워져요."
     - 3행(조회 후): 제조사·차종·연식·연료·주행거리 (위와 동일).
   - 번호 없이 [검증하기]를 누르면, "차량 정보를 입력해 주세요" 또는 "차량번호를 입력하시면 자동으로 채워져요" 유도.

3. **차량 정보 불러오기**
   - 입력된 차량번호로 조회하는 것은 "있는 경우"와 동일.  
   - 조회 실패 시 수동 입력(제조사·차종·연식·연료·주행거리)으로 전환 가능하게 둔다.

### 3.3 UI 배치

- **차량** 카드:  
  - "차량번호" 입력 필드 + [차량 정보 불러오기]  
  - (조회 후) 요약 한 줄 + 주행거리만 수정 또는 전체 수정 가능.

---

## 4. 차량을 미리 등록해 두는 프로세스 (내 차 관리)

### 4.1 목적

- 견적 요청이 아니라 **내 차 관리(/vehicle)** 에서 미리 차량을 등록해 두면,  
  - 다음에 견적 검증할 때 "저장된 내 차 정보 사용" 옵션을 줄 수 있고,  
  - 차량번호만 한 번 등록해 두면 이후에는 번호 다시 안 쳐도 되게 할 수 있다.

### 4.2 흐름

1. **내 차 관리 (/vehicle)**
   - 기존: 차량 정보 요약, 정비 통계, 정비 이력, [차량 정보 수정]/[차량 등록].
   - 추가: **"차량번호로 불러오기"** 블록.
     - 문구 예: "차량등록번호(번호판)를 입력하면 제조사·차종 등이 자동으로 채워져요."
     - 입력란 + [불러오기] 버튼.
     - 클릭 시 `fetchVehicleByRegistrationNumber` 호출 → 결과로 /vehicle/edit 폼에 반영하거나, 같은 페이지 내 인라인 폼에 채움.

2. **차량 등록/수정 (/vehicle/edit)**
   - 상단에 **"차량번호로 불러오기"** 블록 추가.
     - 입력: 차량등록번호 (예: 12가3456).
     - [불러오기] → API(또는 목업) 조회 → 제조사·차종·연식·연료 자동 입력, 주행거리만 사용자 입력.
   - 기존 수동 입력(제조사·차종·연식·주행거리·연료)은 그대로 두고, "불러오기로 채우기"와 "직접 입력"을 모두 선택 가능하게 한다.

3. **견적 플로우와의 연계 (선택)**
   - Review 화면에서 "저장된 내 차 정보가 있어요. 이걸로 할까요?" 체크 또는 버튼을 두면,  
     `fetchVehicle()`로 가져온 한 대를 그대로 쓰고, 차량번호 입력/조회를 생략할 수 있다.  
   - 이건 차량이 이미 한 대 등록된 사용자에게만 노출하면 된다.

---

## 5. 정리: 어떤 화면에서 무엇을 하면 되는지

| 구분 | 화면 | 차량번호 | 동작 |
|------|------|----------|------|
| 견적서에 번호 있음 | Review (견적서 확인) | AI 인식값 표시 + 수정 가능 | [차량 정보 불러오기] 탭 시 조회 → 자동 채움 → 주행거리만 입력/수정 |
| 견적서에 번호 없음 | Review (견적서 확인) | 입력란만 표시 | 사용자 입력 후 [차량 정보 불러오기] → 동일 |
| 미리 등록 | 내 차 관리 / 차량 등록·수정 | 입력란 + [불러오기] | 조회 후 제조사·차종·연식·연료 자동 채움, 주행거리만 입력 |

- **API(또는 목업) 호출 시점**: "차량 정보 불러오기" 버튼을 **눌렀을 때**만 호출. (이미지 분석 직후 자동 조회는 하지 않음.)
- **검증(확인)**: 조회 결과를 보여준 뒤 "이 차량이 맞나요?" 확인·수정할 수 있게 두면 된다.

## 6. 구현 시 참고

- **Server Action**: `fetchVehicleByRegistrationNumber(registrationNumber)`  
  - `lib/supabase/actions.ts`  
  - 목업: `vehicle_lookup_mock` 조회. 실제 연동 시: 자동차종합정보 첨부형API 호출 후 동일 형태로 반환.
- **프로토타입 샘플 번호**: `docs/VEHICLE_LOOKUP_MOCK_PROTOTYPE.md` 참고 (예: 12가3456, 23나1234 등).

이 플로우대로 적용하면, 유저는 견적서에 번호가 있으면 확인만 하고 "불러오기" 한 번, 없으면 번호만 입력하고 "불러오기" 한 번으로 귀찮게 제조사·차종 등을 직접 넣지 않아도 되고, 내 차 관리에서 미리 등록해 두는 경로도 자연스럽게 이어질 수 있다.
